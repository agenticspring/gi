# gi — offline `.gitignore` generator

`gi python node > .gitignore` — instantly generate a `.gitignore` from
bundled, offline templates. No network, no API, no account. Works on planes,
in containers, and in locked-down CI.

## Features

- **22 bundled templates**, shipped as data files inside the package:
  languages (`python`, `node`, `go`, `rust`, `java`, `ruby`, `php`,
  `swift`, `kotlin`, `c`, `cpp`, `dotnet`, `terraform`, `latex`,
  `jupyter`), operating systems (`macos`, `windows`, `linux`), and editors
  (`vscode`, `jetbrains`, `emacs`, `vim`).
- **Merge multiple templates** — `gi python macos vscode` combines them with
  a `# ----- name -----` header per section.
- **Exact-line deduplication** — shared entries (e.g. `.DS_Store`) appear
  only once in the merged output.
- **100% offline** — templates resolve relative to the module, never the
  current directory; works from any cwd with zero network access.
- **Zero dependencies** — Python 3.8+ stdlib only (`argparse`, `difflib`,
  `pathlib`).
- **Friendly errors** — unknown template names exit with code 2 and include
  a close-match suggestion (`gi pythn` → "Did you mean: python?").
- **Pipe-safe** — `gi python | head` exits quietly instead of trace-backing
  on a broken pipe.

## Installation

```bash
git clone https://github.com/agenticspring/gi.git
cd gi
pip install .
```

Or run it without installing, straight from the source tree:

```bash
python3 -m gi.cli python node > .gitignore
```

## Usage

```bash
# Merge templates into a .gitignore (stdout)
gi python node > .gitignore

# ...or write directly to a file
gi python node -o .gitignore

# List all bundled template names
gi --list

# Print one template verbatim
gi --show python

# Combine a language, an OS, and an editor
gi python macos vscode > .gitignore
```

Real output of `gi go rust`:

```
# ----- go -----
# Binaries
*.exe
*.exe~
*.dll
*.so
*.dylib

# Test binary, built with `go test -c`
*.test
# Output of the go coverage tool
*.out
# Compiled output
/bin/
/dist/
# Go workspace files
go.work
go.work.sum
# Dependency directories (uncomment if you vendor)
/vendor/
# Profiling
*.prof
# macOS
.DS_Store

# ----- rust -----
# Generated by Cargo; will have compiled files and executables
/target/
# Remove Cargo.lock from gitignore if creating an executable
Cargo.lock
# Backup files generated by rustfmt
**/*.rs.bk
# MSVC Windows builds of rustc generate these
*.pdb
```

Note how `.DS_Store` (present in both the `go` and `rust` templates) is
emitted exactly once — the merge deduplicates identical lines.

## Bundled templates

| Category | Templates |
|---|---|
| Languages | `c`, `cpp`, `dotnet`, `go`, `java`, `jupyter`, `kotlin`, `latex`, `node`, `php`, `python`, `ruby`, `rust`, `swift`, `terraform` |
| Operating systems | `linux`, `macos`, `windows` |
| Editors | `emacs`, `jetbrains`, `vim`, `vscode` |

Template names are case-insensitive. Run `gi --list` for the authoritative
list.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success (also when a downstream pipe closes early) |
| `1` | Internal error (missing template bundle, unwritable `-o` path) |
| `2` | Usage error (no templates given, unknown template name) |

## Limitations

- Templates are curated, hand-written snapshots — they cover the common
  build artifacts, dependency directories, and editor files for each
  ecosystem, but they are not exhaustive. Contributions of new templates or
  entries are welcome.
- Merging deduplicates **exact lines only**; semantically overlapping but
  textually different patterns (e.g. `build/` vs `/build/`) are both kept.
- Unlike network-backed generators, `gi` cannot fetch templates for tools
  it does not bundle. That is the trade-off for being fully offline.
- This repo's own `.gitignore` was generated by the tool itself:
  `python3 -m gi.cli python > .gitignore`.
